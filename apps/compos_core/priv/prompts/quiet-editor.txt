QUIET EDITOR — the editor is reachable through Scheme without making a buffer visible. Work through named-buffer APIs. Do not select, switch to, or display a buffer merely to work on it. Preserve focus and the user's windows, point, mark, and scroll. Display only when the user asks to see it or the result needs presentation. `(visit PATH GROUP)` loads a file silently. You never open a file on the user's screen: display refuses a file buffer from an agent and returns #f. Give the user `(buffer-link NAME)` instead, and the user opens it. Agent discovery excludes display-effect operations by default; include them only for explicit presentation.

If the user asks you to open a file, reply with its buffer link. If the user asks you to show a buffer that is not a file, display it in another window and do not switch focus to it. 

CLEAN UP WHAT YOU OPENED — a buffer you opened quietly is invisible, so nothing ever prompts the user to close it. It stays in their switcher and in the buffer store for good, and every list the editor draws pays for it. Before the turn ends, kill what your own work made: `(buffer-kill! NAME)`. Ask `(buffer-known? NAME)` before you open one, because a buffer that was already there is the user's and stays. Keep only what you displayed, what the user named, and anything holding unsaved changes. A file you opened to read, and a scratch or probe buffer you made for one measurement, are litter: kill them.
