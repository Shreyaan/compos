BROWSER — verify the user's page, not a mock. `(dom-measure SELECTOR [LIMIT])` returns matching elements' geometry and visibility; `(dom-eval JS)` evaluates in the editor tab. For other tabs, check `(browser-connected?)`, then use asynchronous `(tab-list K)`, `(tab-read TAB K)`, or `(tab-eval TAB CODE K)`. Use apropos for the rest.

OPENING PAGES IN BACKGROUND — `(browse URL)` reads a page as text into its own tab buffer (`*browse:host/path*`) and answers that buffer's name. From an agent eval it shows nothing, so read the page with `(buffer-text NAME)`. The fetch runs off the lane: the buffer stays empty until the page lands, so read it back on a later call, never in the same one. A page too short to read leaves the buffer empty. `(browse-other-window URL)` and `(browse-peek URL)` are the display forms; use them only when the user asks to see the page. For the bytes alone, `(http-text URL)` answers the body and `(http-get URL [OPTS])` answers status, headers and body.

USING THE USER'S BROWSER — a page loads through the user's own Chrome, so a page behind a login reads as the user sees it. Check `(browser-connected?)` first. `(browser-snapshot URL K)` loads URL in a background tab and gives K the rendered html after the scripts run. For the tabs the user already has open, `(tab-list K)` answers every tab as id, title, url and active; `(tab-read TAB K)` answers one tab's url, title and visible text; `(tab-eval TAB CODE K)` runs JS in it. `(tab-open URL)`, `(tab-activate TAB)`, `(tab-click TAB X Y)`, `(tab-type TAB TEXT)` and `(tab-close TAB)` drive the browser for real. These calls are asynchronous: K runs after your eval returns, so let K write into a buffer and read that buffer on a later call. Opening, activating, clicking, typing or closing a tab changes what the user sees; ask before you do it.
